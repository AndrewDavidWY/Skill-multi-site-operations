# 访问、验真与每日运行

## 首选最小权限

先复用已连接的只读工具。需要新接入时，向用户说明哪些 property、哪些聚合数据、哪个身份、存储位置和用途。通常请求 property 范围的 Viewer 能力及只读分析 scope；不要默认要求账户 Administrator。已有成本/收入限制按实际保留，缺少某指标不代表应提升权限。

服务账号凭据、refresh token 和 OAuth 授权属于持久访问。通过环境提供的安全授权机制配置，遵循执行环境的逐次批准要求；不在聊天或公有仓库粘贴。授权数据读取不自动授权公开业务指标。

官方依据：[角色与数据限制](https://support.google.com/analytics/answer/9305587)。

## 三层验真记录

1. **测量层**：实际网站发出正确 property/stream 的事件；同意管理、重复标签、SPA 路由和测试过滤符合现有设计。没有授权不主动提交真实线索、支付或其他业务交易来做测试。
2. **报告层**：UI 与导出/API 同口径核对，记录时间与差异；近期报告仍可能处理变化。原始请求、行数、分页和质量元数据保留在受控存储。
3. **运行层**：手工采集成功、计划配置存在、真实定时执行成功、结果交付成功分别记录。不要用配置截图代替运行日志。

官方参考：[采集排障](https://developers.google.com/analytics/devguides/collection/ga4/troubleshoot)、[报告数据预期](https://developers.google.com/analytics/devguides/reporting/data/v1/reporting-data-expectations)。

## 调度与失败

只有本次请求包含持续任务才启用调度。指定时区、报告窗口、站点、接收人、保存位置和通知条件；跨站时区不同须清楚说明各站日界线。固定时间生成日报可晚于部分属性的报告成熟时间，也可能仍需标记 provisional。

按 `site_id + report_date + contract_version` 幂等写入选定版本；保留修订时间和原取数时间。不要每次失败都追加同一天的数据或覆盖最后成功数据而不留标记。

对 429/临时 5xx 采用有限退避；对权限拒绝、无效 property、指标不兼容等确定错误停止受影响站点并报告。设置失败阈值、最近成功时间和过期标记，不把错误变成零。扩大权限或更换数据源需按当前授权重新确认。

## 变化解释

先核对口径、采集状态、处理延迟、周末/节假日与样本大小，再提出业务解释。数字变化不自动证明某次改版或营销活动造成了变化。建议中分开观察、推测和需验证的行动。
